# 小程序客服“用户档案”场景联调测试报告

## 1. 结论

联调服务使用客服免登 token 读取列表内患者的档案接口正常，未复现“服务端不返回用户档案”。正确入口是 `GET /api/v1/patients/{patientId}/profile`。

已实测患者501、502、910005，均返回HTTP 200、业务 `code=0`，且 `data.patient` 非空。501有病历；502及910005的 `data.medicalRecord={}`，表示尚无病历内容，不代表患者基本档案为空。

客服调用 `/api/v1/doctor/patients/501/archive` 返回HTTP 200、业务 `code=403`、`message=无权限访问`。该接口只授权DOCTOR，不能用来承接客服按钮。

尚未获取实际小程序网络请求URL、响应或取值代码，因此不能认定前端一定调用了医生接口。当前证据只证明正确档案接口对测试客服及其列表内患者可用。

## 2. 场景与接口映射

前端反馈路径：小程序客服登录 → 用户列表 → 点击用户打开健康管理群弹框 → 顶部“用户档案” → 用户基本信息弹框。

原型定位：

- `custom_prd_1104/src/app/views/cs/Home.tsx`：列表通过 `setChatPatientId(p.id)` 打开 `HealthGroupChat`。
- `custom_prd_1104/src/app/components/HealthGroupChat.tsx`：按钮“用户档案”设置 `showPatientInfoModal=true`，弹框复用 `PatientBasicInfoView`。
- 原型数据来自演示store，按钮本身没有真实网络请求。因此服务端接口映射由当前Controller/契约及实测确定，不能据原型断言上线小程序的实际请求。

| 需求 | 正确接口 | 取值 |
|---|---|---|
| 用户档案聚合 | `GET /patients/{patientId}/profile` | `data.patient`、`data.medicalRecord`、`data.serviceRelations` |
| 仅基本信息 | `GET /patients/{patientId}` | `data` 是患者实体 |
| 客服详情/手术档案/沟通时间线 | `GET /cs/patients/{patientId}` | `data`，含surgeryArchive等 |
| 健康数据汇总 | `GET /patients/{patientId}/health-summary` | `data`，按健康模块分组 |
| 医生10模块临床档案 | `GET /doctor/patients/{patientId}/archive` | 仅DOCTOR，客服不可调用 |

`patientId` 使用客服用户列表行的 `id`，不要使用聊天 `conversationId`。例如本报告验证的是患者501，不是会话601。

## 6. 前端排查与取值示例

按以下顺序核对：

1. 网络面板中实际URL是否为 `/api/v1/patients/{patientId}/profile`，且patientId是列表行id。
2. 请求头是否是 `Authorization: Bearer <cs token>`，不是只传token字符串。
3. 检查响应体code；HTTP 200不等于业务成功，403/401等需按业务错误处理。
4. 若请求封装已解包Result.data，读取 `profile.patient`；若没有解包，读取 `response.data.patient`。
5. 基本信息和病历分开映射，不能只取medicalRecord，不能把聚合data直接当作扁平患者对象。无病历时也应展示基本信息和“暂无病历”。

以浏览器fetch未自动解包为例：

```javascript
const response = await fetch(`${baseUrl}/patients/${patientId}/profile`, {
  headers: { Authorization: `Bearer ${csToken}` },
});
const result = await response.json();
if (result.code !== 0) throw new Error(result.message || '获取用户档案失败');
const patient = result.data.patient;
const medicalRecord = result.data.medicalRecord || {};
const serviceRelations = result.data.serviceRelations || {};
// 将patient作为PatientBasicInfoView的基础信息来源，病历字段从medicalRecord单独映射。
```

若使用Axios且封装没有解包，Axios的response.data才是统一Result，对应基本信息路径为 `response.data.data.patient`；需要按项目封装实际行为选择，不能机械追加/删除data层。

若字段需要医院/科室/医生名称，还须按已有字典/关系数据映射；不要将hospitalId等数值字段直接当作名称。
