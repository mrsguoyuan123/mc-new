### 1.1 统一响应（最重要的一条）

**HTTP 状态恒为 200**，一切语义看响应体 `code`：

```json
{ "code": 0, "message": "ok", "data": { } }
```

| code | 含义 | 前端处理（必须按此约定实现） |
|---|---|---|
| 0 | 成功 | 取 `data` |
| 400 | 业务错误（参数、密码错、资源不存在、限流、微信 code 过期等） | 弹 `message`，**不跳登录** |
| 401 | access token 缺失/过期/非法 | ① 用 refreshToken 调 `/auth/refresh` 静默换新 ② 重试原请求一次 |
| 402 | refreshToken 无效/已过期 | 清本地凭证 → 跳登录页 |
| 403 | 无权限（如患者调后台接口） | 提示无权限 |
| 500 | 服务端异常 | 通用错误提示（可带上 message） |

分页统一结构：`data = { "list": [], "total": 100, "page": 1, "pageSize": 20 }`。
鉴权头：`Authorization: Bearer <accessToken>`（除公开接口外一律携带）。

## 2. 登录方式总览

| 角色 | 登录方式 | 接口 |
|---|---|---|
| 用户（患者） | 微信一键登录；手机号验证码登录；手机号验证码注册 | `/auth/wx-login`、`/auth/sms-login`、`/auth/register` |
| 客服 / 驻点 / 医院管理（员工） | 账号密码（PC 端人员管理创建账号） | `/auth/login` |
| 公司管理 | 账号密码 | `/auth/login` |

**登录成功的响应都带 `user`（含 role）**；患者侧三个入口返回的 role 恒为 `PATIENT`。

## 3. 详细流程（请求/响应示例）

### 3.1 微信一键登录（含新用户注册绑定）

```
POST {base}/auth/wx-login?code=<wx.login 的 js_code>       ← 公开接口
```

**分支 A：openid 已绑定（老用户）**

```json
{ "code": 0, "data": {
    "token": "eyJhbGci...（有效期 2h）",
    "refreshToken": "eyJhbGci...（有效期 7d）",
    "user": { "userId": 910005, "username": "13800000005",
              "role": "PATIENT", "hospitalId": null, "deptScope": null, "departmentId": null },
    "needRegister": false
}}
```

**分支 B：新用户**（服务端查无此 openid，openid 已暂存 Redis 30 分钟）

```json
{ "code": 0, "data": { "needRegister": true, "bindToken": "8f3a...（30分钟有效、一次性）" } }
```

→ 前端跳注册页，用户填**姓名、身份证、医院、科室、主治医生、病症介绍** + 手机号验证码：

```
POST {base}/auth/sms-code        { "phone": "13800001111" }     ← 60 秒倒计时限频
POST {base}/auth/register        {
    "phone": "13800001111", "code": "短信验证码",
    "name": "小赵", "gender": "男", "idCard": "330102198001011234",
    "hospitalId": 1, "departmentId": 301, "doctorId": 901,
    "diseaseIntro": "胃肿瘤术后",
    "bindToken": "8f3a...（wx-login 拿到的，带回即完成 openid 绑定）"
}
```

→ 返回同分支 A 的完整登录态（**注册即登录**）。
特殊情况：手机号已注册但没绑 openid → 带有效 bindToken 时服务端自动补绑并直接登录；不带则返回 400"该手机号已注册"。

### 3.2 手机号验证码登录（不依赖微信，换设备兜底）

```
POST {base}/auth/sms-code        { "phone": "13800000005" }
POST {base}/auth/sms-login       { "phone": "13800000005", "code": "123456" }
→ 响应同 3.1 分支 A（role=PATIENT）
```

### 3.3 员工/管理员账号密码登录

```
POST {base}/auth/login           { "username": "admin", "password": "admin123" }
```

```json
{ "code": 0, "data": {
    "token": "...", "refreshToken": "...",
    "user": { "role": "ADMIN", "userId": ..., "hospitalId": null, ... }
}}
```

- 客服/驻点/医院管理账号由 PC"人员管理"创建（初始密码 123456，可改）
- 医院管理登录后 `user.hospitalId`/`user.deptScope`（HOSPITAL 医院权限/DEPT 科室权限）有值——**前端按 deptScope 决定患者列表是否显示科室筛选**（DEPT 时按需求隐藏筛选）

### 3.4 刷新与登出

```
POST {base}/auth/refresh?refreshToken=xxx      ← 成功换回一对新 access+refresh（旧的 refresh 作废）
POST {base}/auth/logout?refreshToken=xxx       ← 注销 refresh token（多设备不互相影响）
```

- **多设备登录允许**：每台设备各持一对 token，互不剔除；登出只注销本设备 refresh token
- `GET {base}/auth/me`：只有 token 时拿身份/角色/数据范围（启动恢复会话、401 探测用）

### 3.5 登录成功后的角色渲染

| role | 手机端 tab | 备注 |
|---|---|---|
| PATIENT | 首页 / 消息 / 健康管理 / 我的（4 tab） | 消息=健康团队管理群 |
| CS | 患者 / 我的（2 tab） | 患者列表=PC 匹配给该客服的患者 |
| STATION | 患者 / 陪诊服务 / 我的（3 tab） | 患者列表=PC 匹配给该驻点的患者；无拨打电话权限 |
| HOSPITAL_ADMIN | 患者 / 我的（2 tab） | 患者列表=本医院（或本科室）患者 |
| ADMIN（仅 PC） | 后台菜单 | 全量 |

## 4. 前端统一封装（拦截器伪代码）

```js
async function request(method, path, body, retried = false) {
  const resp = await fetch(BASE + path, {
    method: method || 'GET',
    headers: {
      'Content-Type': 'application/json',
      ...(getToken() ? { Authorization: 'Bearer ' + getToken() } : {}),
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  const r = await resp.json();                    // HTTP 永远 200，只看 code

  if (r.code === 0) return r.data;                                   // 成功
  if (r.code === 401 && !retried) {                                  // access 失效
    const rf = await fetch(BASE + '/auth/refresh?refreshToken=' + getRefreshToken()).then(x => x.json());
    if (rf.code === 0) {
      saveToken(rf.data.token, rf.data.refreshToken);                // 换新（refresh 轮换）
      return request(method, path, body, true);                      // 原请求重试一次
    }
    // code=402：refresh 也失效 → 清凭证回登录
    clearAuth();
    jumpToLogin();
    return;
  }
  if (r.code === 403) return toast('无权限');
  toast(r.message);                             // 400 / 500 只提示，不动登录态
}
```

微信小程序记得把 `token` 一起拼进 WebSocket 连接：`wx.connectSocket({ url: WS_URL + '?token=' + token })`，事件 `message.new`（新群消息）/ `notification.new`（通知）等。

## 5. dev 静态 token（联调免登，仅 dev profile）

**用途**：跳过登录环节，每角色直接拿一个时序一年的 access token。**生产 profile 该机制不生效（接口 404）**。

```
GET {base}/auth/dev-tokens          ← 免鉴权
```

```json
{ "code": 0, "data": {
    "admin":   "eyJ...（ADMIN）",
    "hospital": "eyJ...（HOSPITAL_ADMIN，hospitalId=1，医院权限）",
    "cs":      "eyJ...（CS）",
    "station": "eyJ...（STATION）",
    "patient": "eyJ...（PATIENT）"
}}
```

**用法**：请求头 `Authorization: Bearer <上面拿到的 token>`；WebSocket 同样把该 token 拼 `?token=`。

**配合种子数据（dev 自动写入，可直接验证业务接口）**：

| 用哪个 token | 固定 userId | 有数据的接口举例 |
|---|---|---|
| patient | 910005（患者"王五"，已加入沟通群 603） | `/me/conversations`、`/me/health-records`、`/me/escort`、`/conversations/603/messages`、`/me/scales/psqi` |
| cs | 910003 | `/patients`（3 个匹配患者 501/502/910005）、`/follow-up/tasks`、`/risk-alerts`、`/conversations/601/messages`、`/notifications` |
| station | 910004 | `/patients`（2 个匹配患者 501/910005）、`/escort/tasks?status=PENDING`（任务 1101） |
| hospital | 910002（hospitalId=1） | `/hospital/patients`（3 人）、`/hospital/patients/501/health-detail`（7/30 天趋势）、`/patients/501/scales` |
| admin | 910001 | 全量：`/staff`、`/accounts/operation-logs`、`/dict/*`、`/escort/bookings` |

注意：
- **每次服务重启 token 会重新生成**（固定的是 userId 角色映射，不是 token 字符串）；启动日志里也会打印
- 静态 token 是**真实 JWT**，走完整鉴权链路（401/402/403 行为与正常登录一致），唯一区别是不经过登录接口
- 虚拟 userId 只与种子数据匹配；对患者列表这类"按匹配关系过滤"的接口，非种子患者不会出现

## 6. 常见坑速查

1. **验证码**：60 秒限频（同手机号），5 分钟有效；dev 环境验证码打印在服务器日志 `[MOCK-SMS]`，本地没接真实短信时去日志里翻
2. **wx-login 的 code**：一次性、5 分钟有效，用过再传会 400；真机/开发者工具才能产生有效 code，`dev-tokens` 的假 token 替代不了这一步
3. **微信合法域名**：真机调试需在公众平台配置 request/socket 合法域名（已备案 + HTTPS）；开发者工具可临时勾选"不校验合法域名"
4. **发消息幂等**：`POST /conversations/{id}/messages` 支持 `clientSeq`，网络重试带上同一 clientSeq 不会产生重复消息（服务端返回原消息）
5. **PSQI 提交**：答案字段见 `GET /me/scales/psqi`（q1~q4、q5a~q5j、q6~q9），漏答返回 `valid=false` 不生成结果；种子样例答案计分 = 7 分"轻度"
6. **陪诊预约**：先 `GET /me/escort/slots?date=&stationId=` 拿 2 小时排他空档；预约不扣次数、取消不返还、服务完成扣 1
7. **转人工**：只有患者点"人工服务"（`POST /conversations/{id}/manual-service`）才会触发 PC 客服提醒，AI 不会自动转人工
