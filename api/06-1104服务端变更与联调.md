# 1104 服务端变更与联调

2026-11-05。基线：`custom_prd_1104/`、`management_demo_1104/`，以及用户明确确认。服务端实现包含前两项登录/群医生调整和全量原型差异。源原型不改写；接口模型以本次生成的 swagger.json 为准。

## 覆盖清单

| PRD变化 | 服务端落地 |
|---|---|
| 后台管理账号、手机号关联、无小程序角色选择 | 统一短信登录；关闭自助注册；微信验证手机号关联既有账号；V18 |
| 多医生协作 | 后台明确群名单；群内发言/本人编辑/艾特/实时消息；V19；临床范围不扩大 |
| 专属驻点、患者只选时间 | 使用后台匹配关系；无匹配拒绝；保留日期/时段/配额约束 |

| PC驻点服务记录与完整性 | 范围过滤的列表、详情、统计；完整/未完整反映真实历史证据 |
| 患者健康总览/异常标签/健康筛选 | 批量健康快照、同范围汇总、动态风险分类 |
| 客服健康异常待办与处理 | 实际异常记录/评估生成risk_alert；范围校验及幂等处理 |
| 消息模板、触发规则、发送/阅读记录 | 消息中心CRUD/启停/过滤/统计，真实投递台账；V21 |
| 小程序红点与首页提醒 | 分类未读、类别清理、会话已读同步、当前模板/规则生效 |

| 其他健康记录、OCR、运动、睡眠、看板 | 复用现有业务；纯UI/文案/演示样例不新增模型 |

## 移动端接入调整

### 登录与群聊

- `/auth/sms-login {phone,code,bindToken?}` 使用后台预置身份；`/auth/register` 固定业务错误。
- 微信未绑定返回 `needBindPhone=true`，验证手机号后关联，不跳注册页。
- 医生 `/me/conversations` 只返回后台加入的群；主治/主管关系不会自动授予群权限。
- `/conversations/{id}/doctors` 返回医生库ID。发消息 `mentionDoctorIds:[dict_doctor.id]`，校验后的名单在 `extraJson.mentionDoctorIds`。
- `message.new` 包含医生发言；`notification.new` 按PATIENT/STAFF身份推送。

### 专属驻点与现场证据

1. 后台配置患者 `matchedStationId`。`GET /me/escort` 返回 `dedicatedCaregiverId`；原陪诊师列表只返回绑定人员。
2. `POST /me/escort/bookings {serviceDate,period,departmentId?,remark?}`，caregiverId不再必填，若传入其他人则400。period沿用 MORNING/AFTERNOON/FULLDAY。
3. 待接单→确认→服务日开始。`GET /escort/active-service` 为当前活动订单，便于跨页面恢复。
4. 先通过文件上传获取真实照片URL，然后 `POST /escort/orders/{id}/checkin`：

```json
{"latitude":30.25,"longitude":120.16,"address":"门诊楼","photos":["/files/checkin/example.jpg"],"capturedAt":"2026-11-05T09:00:00"}
```

capturedAt为实际拍摄时间，不能在未来；照片必须1-3张。示例时间应替换为实际值。

5. 提交 `/escort/orders/{id}/service-record`，recoveryDescription/otherSituation/taskCompleted必填。otherSituation为NORMAL/EMPTY_NESTER/MOBILITY_IMPAIRED/OTHER；taskCompleted为COMPLETED/INCOMPLETE。结束时间checkoutAt由服务端记录，不新增虚假离院打卡。没有已保存证据时拒绝归档；重复完成不重复记录/累加。

### 红点与私有留言

- `GET /notifications/unread-summary`：`userUnreadMessages`、`userHealthAlertCount`、`systemUnreadCount`、`doctorMentionCount`、`doctorNoteCount`。
- 患者查询该汇总时，按真实用药日期/时段与打卡、运动完成/暂停、PSQI30天有效期惰性生成每日提醒；事件按来源/日期防重。它不是离线定时推送服务。
- `PUT /notifications/read-category {category}`，支持HEALTH/SYSTEM/DOCTOR_MENTION/DOCTOR_NOTE/ALL。聊天仍调用 `/conversations/{id}/read`，同时清理相应群消息/客服回复/艾特通知。
- 医生 `GET /doctor/notes?patientId=&isRead=&replied=&page=&pageSize=`；打开留言调用 `PUT /doctor/notes/{id}/read`；已处理回复调用 `PUT /doctor/notes/{id}/replied`。这仅标记回复状态，不替代实际沟通内容。
- `/doctor/notes/unread-counts?patientIds=...` 返回本人各患者未读数；患者列表含doctorNoteUnread。每位医生回执独立，不影响其他收件人。

## PC 接入调整

### 健康数据与风险

- `/patients` 每行增加 `healthSnapshot` 和实时 `healthStatus`；`healthStatus=NORMAL|ATTENTION|ABNORMAL` 在分页前过滤。
- `/patients/health-overview` 返回范围内 `total/normal/attention/abnormal/noData/pendingAlerts`，统计口径为筛选前可访问患者。
- `/patients/{id}/health-snapshot` 包含各类型最新记录/日期、weight7dChange、今日用药、有效PSQI、运动方案和今日完成状态、reasons、pendingAlerts。
- 无数据用NO_DATA/null，不制造指标或临床正常结论。未取得准确7日前基线时weight7dChange为空。
- `/risk-alerts` 列表/summary/处理受同一患者范围约束；处理`{status:HANDLED|CLOSED,note?}`幂等。仍存在的异常指标/暂停状态不会因处理提醒被隐藏。
- 异常生产仅认可记录明确status=ABNORMAL/isAbnormal或真实异常运动评估；不照搬演示血压/血糖阈值作医学判定。

### 消息中心

需 `message:manage`，默认公司管理员获得该权限。

- `/message-center/templates` GET/POST；`/{id}` PUT/DELETE；`/{id}/status` PUT `{status:ENABLED|DISABLED}`。
- 模板字段：name、scene、channelsJson、title、content、variablesJson、status。channelsJson/variablesJson是JSON数组字符串；占位形式`{{用户姓名}}`，必须声明且提供变量。
- `/message-center/rules` GET，`/{id}` PUT；保留scene/code不可改，配置name/rolesJson/redDot/jump/enabled。
- `/message-center/records` GET，按scene/sendStatus/isRead/source/keyword/userId/userType/channel/startTime/endTime/page/pageSize筛选；附userName/templateName。
- `/message-center/statistics` GET，返回total/success/failed/pending/unread/successRate/readRate及分场景统计；空分母返回0。
- 渠道IN_APP/BADGE/HOME_CARD均为系统内部展示，不代表微信订阅或短信平台已送达。模板变量缺失记FAILED，不向用户展示未渲染内容。读取通知即更新同一投递记录。
- 群消息/客服回复、陪诊状态、医生留言、明确健康异常均接入事件。HEALTH_ALERT规则和SLEEP_REMINDER默认关闭，按业务配置启用。医生留言/艾特与群消息属于不同提醒；不重复累加聊天未读。
- FOLLOWUP_REMINDER提供场景配置/投递能力，但不将客服电话随访计划当作临床复诊计划，也不伪造未来复诊日期。

### 医生群与私有问题

- `/conversations/{id}/doctors` PUT全量替换，空数组清空；chat:assign权限+ADMIN/CS患者范围。
- 患者profile/relations返回conversationId、healthManagementDoctorIds；无群/无成员为空，不自动回退主治。
- `POST /patients/{patientId}/doctor-notes`：question、priority=NORMAL|IMPORTANT、doctorIds（医生库ID）、clientSeq?。
- 收件人只能是患者主治/主管或后台群医生；服务端准备其技术账号以保存离线提醒。`GET`同路径查询留言及逐医生回执。公开群与患者均不能读取这些私有问题。

### 服务记录

- `/escort/service-records`、`/stats`、`/{id}`：service:escort:manage及患者数据范围。
- 筛选patientId/caregiverId/keyword/taskCompleted/from/to；列表另含page/pageSize。详情包含checkins、照片capturedAt、checkoutAt、反馈和traceComplete。
- 汇总total/withLocation/withPhotos/traceComplete/completeRate按同一筛选范围。历史缺证据保留缺失，不假填时间。
- 后台预约编辑/改派对旧/新驻点有序加锁，再锁订单并读取最新状态，冲突检查使用当前读，防止取消后被旧数据写回。

## 迁移和验证边界

只追加 V20/V21/V22：陪诊留痕字段、消息模板规则及通知台账、私有医生留言及回执。V1-V19不修改。新群医生仍须后台显式配置；新患者必须匹配驻点才可预约。

本次不部署、不对生产库执行迁移。全链路冒烟脚本依赖专用dev MySQL/Redis并重置测试数据，只能在该环境执行。自动测试、编译及Swagger生成物/Controller路由校验结果以交付回复为准。
